# Анализ пользовательского теста

Скрипт проверяет различия между четырьмя условиями управления и изменение разрыва
между тачем и жестами. План эксперимента и определения метрик приведены в
[RESEARCH.md](../docs/RESEARCH.md#часть-2-пользовательский-тест).

## Запуск

Из корня репозитория с Python 3.12.

```bash
python -m pip install -r analysis/requirements.txt
python -m unittest discover -s analysis -v
MPLBACKEND=Agg python analysis/user_study.py /path/to/blocks.json --plot /path/to/learning.png > /path/to/report.json
```

Вход — подготовленные из логов и анкет наблюдения. Это промежуточный файл для
анализа, формат сырого экспорта приложения описан в
[ARCHITECTURE.md](../docs/ARCHITECTURE.md#формат-записей). Держите вход и отчёт вне git.

```json
{
  "blocks": [{
    "participant_id": "P01",
    "condition": "touch",
    "position": 1,
    "completed": true,
    "successes": 2,
    "errors": 1,
    "misses": 1,
    "cancelled": 0,
    "false_positives": 0,
    "gesture_latency_ms": 40,
    "trials": [{"success_ms": 900}, {"success_ms": null}, {"success_ms": 650}],
    "tlx": [30, 20, 35, 20, 35, 10],
    "convenience": 6,
    "control": 5,
    "fatigue": 2
  }]
}
```

Обязательны код участника P01–P12, условие (`touch`, `threshold`, `dtw`, `camera`)
и позиция 1–4. Одна строка соответствует одному участнику в одном условии. Для
прерванного блока укажите `completed: false`. Если блок повторили, укажите выбранную
для анализа запись в соответствии с протоколом и сохраните историю в исходных логах.

- `trials` перечисляет завершённые исходы духов в порядке появления. Время указывается
  в миллисекундах от появления до успешного действия. Для пропуска укажите `null`.
  Успех, откаченный отменой, учитывайте по окончательному исходу духа.
- `successes` — число обработанных духов, `misses` — число пропущенных. Если передан
  `trials`, доля успехов и медиана времени рассчитываются по нему. Без `trials`
  доля рассчитывается из `successes` и `misses`, время остаётся пустым.
- `errors`, `cancelled` и `false_positives` — счётчики по определениям плана исследования.
  `gesture_latency_ms` — медиана задержки по блоку, если она доступна.
- `tlx` содержит шесть оценок 0–100 в порядке анкеты. Вопрос о результативности
  кодируется от хорошей работы (0) к плохой (100). Итог — среднее всех шести
  оценок. `convenience`, `control` и `fatigue` — ответы по шкале 1–7.
- Опциональные метрики можно опустить или указать `null`. Отсутствие измерения
  сохраняется как пропуск. Для истинного отсутствия ошибок или отмен укажите 0.

## Отчёт

- `by_condition` и `by_position` — отдельные сравнения по метрикам. Для каждой
  метрики берутся участники с полным набором наблюдений. Приведены Фридман
  с W Кендалла и парные тесты Уилкоксона с поправкой Холма по шести парам.
  Знак рангово-бисериальной корреляции соответствует разности «левое − правое».
  P-значение Фридмана использует приближение хи-квадрат, его точность ограничена
  при четырёх условиях. Для Уилкоксона перебираются смены знаков при n ≤ 12.
- `learning.curves` — медиана времени среди успешных действий и доля успехов по
  порядковому номеру духа. Для каждой точки приводится число участников.
- `learning.h5` — парное сравнение разницы между тачем и каждым жестовым
  условием в двух половинах блока. Положительный `*_gap_shrink` означает
  уменьшение преимущества тача. Для времени учитываются участники с успешным
  действием в обеих половинах обоих условий. Для доли успехов остаются и
  нулевые половины. Холм применяется к доступным тестам H5 по обеим метрикам.
- `impressions` — исследовательские корреляции Спирмена между впечатлениями и
  объективными метриками внутри каждого условия. Сопоставление с интервью
  делается по анонимному коду отдельно.

Документация статистических методов. [Фридман](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.friedmanchisquare.html),
[Уилкоксон](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.wilcoxon.html),
[Спирмен](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.spearmanr.html).
